## 一、设计理念

> 「让阅读，在时间里生长。」

首页不应是一张贴图，而是一幅 **会呼吸的纸面山水**。用户在任意时间打开墨园，看到的是：

- **天光流转**：晨起纸白，正午微青，暮色琥珀，深夜墨蓝；
- **远近分明**：远山如水洗、雾锁其间，草坪浮于纸上；
- **季节自远而近**：春花瓣随风入画，秋落叶带着叶脉旋下，夏夜一点流萤，冬雪静覆远山；
- **动静相宜**：粒子慢慢飘、远山缓缓漂、云带轻声流——速度控制在「有心方见」之间；
- **绝不打扰**：忌高饱和、忌快闪、忌具象小昆虫、忌警示性动画；一切以"久看不厌"为准绳。

整体气质：**宋代院体小品 × 现代扁平层级**，留白即气韵。

## 二、为什么旧版没有「山、月、萤火」？

旧代码管线（`drawScene`）由四步组成：backdrop（仅天空渐变 + 一点光晕） → weatherEffect（雨雪雾云） → **drawWeatherDecorations**（太阳、月亮、飞鸟、花瓣、落叶、萤火虫） → drawGardenLawns。两类关键问题：

| 问题 | 原因 | 影响 |
|---|---|---|
| 「远山都没了」 | `drawBackgroundLayer` / `drawMountainLayer` 已被排除在活动管线外，全工程仅在 `GardenRenderer.kt` 内部出现，**无任何调用点** | 远山不显示，背景扁平 |
| 「落叶萤火虫错了」 | 旧粒子用 `Random(20260719L)` 取种子 + 一次性坐标，**粒子位置完全静止** | 花瓣/萤火虫像贴在画上的死图 |
| 「下雨太阳月亮很怪」 | `cx = w*0.88, cy = h*0.05, r=34`，**半径仅 34px** 放在画面右上小角；落日 `r = h*0.006`（约 7.8px）几乎不可见 | 与"庭院夜空"气韵相悖 |
| 「萤火虫像昆虫」 | 画了椭圆身体+触须+头部 | 拟真过头，不像"光" |
| 「整体氛围过于平面」 | backdrop 仅一条线性渐变 + 一点径向光 | 缺乏空间纵深 |

## 三、新场景 · 八层堆叠模型

从后到前，每层 **独立函数 / 独立随机种子 / 独立相位**，可单独开关或单独测试。

```
┌──────────────────────────────────────┐  ← top
│  L1  纸张天空（Paper Sky）         │  上下渐变 + 极淡横向笔触
│  L2  天体（Celestial）             │  太阳 | 落日 | 月 + 星；按时辰切换
│  L3  远山三叠（Distant Range）     │  视差漂移 + 季节色偏 + 雪线
│  L4  山脚云雾（Mist Band）         │  两条横向流动雾
│  L5  浮云（Clouds, 限多云）        │  三层云，决定昼/夜照明
│  L6  花园（Garden）                │  菱形草坪 × 植株（含微风轻摆）
│  L7  天气粒子（Weather Particles）  │  雨 / 雪 / 雾
│  L8  四季氛围（Seasonal）          │  花瓣 | 落叶 | 萤火 | 飞鸟
│  +L9 暗角（Vignette）              │  聚焦花园
└──────────────────────────────────────┘
```

### 3.1 渲染层级说明

| 层 | 函数 | 启停条件 | 动画相 |
|---|---|---|---|
| L1 | `drawSky` | 始终 | 静态（带纸张笔触） |
| L2 | `drawCelestial` | 按 hour + weather | sun 微微脉动；moon 呼吸光晕；星闪烁 |
| L3 | `drawMountains` | 始终 | 三层不同速率漂移（1.2 / 2.0 / 3.2 px·s⁻¹） |
| L4 | `drawMist` | 始终（季节调色） | 横向 6~10 px·s⁻¹ 流动 |
| L5 | `drawClouds` | weather==CLOUDY 或 night | 慢飘 |
| L6 | `drawGarden` | 始终 | 植物 micro sway `sin(t·1.1+i·0.72)` |
| L7 | `drawRain/Snow/Fog` | weather 决定 | 雨=竖斜 600~880 px·s⁻¹；雪=60~90 px·s⁻¹ + 摆动 |
| L8 | `drawPetals/Leaves/Fireflies/Birds` | 季节 + 天气 + 时辰 | 见下文 |

### 3.2 顺序契约（必须有，否则视觉立刻塌陷）

1. L1 → L2 → L3 → L4 → L5（先天地）
2. L6 花园（草坪 + 植物 + 夜色压暗层必须绘制在粒子**下面**，否则雨会穿墙）
3. L7 雨/雪/雾（落在整庭）
4. L8 四季氛围（自然环绕，最上层）
5. L9 暗角收尾

## 四、时辰系统（核心 · 替换旧版硬编码 6~17/17~19/19~5）

不再用 `if (currentHour in 6..17)`，而是按关键帧插值：

```
hour → sky top / horizon / 环境亮度 / 远山墨色 / 是否夜景
0:00   #353D46  #4A5258  light=0.28  ink=#39424B  ✦夜
 4:30  #3A424A  #535B60  light=0.30  ink=#3D454E  ✦夜
 6:00  #C9C3B4  #E7D9C0  light=0.72  ink=#8A9088  ☀晨曦
 7:30  #EFEBDD  #F2ECDB  light=0.97  ink=#9AA79B  ☀昼
12:00  #F4F1E6  #EFEADA  light=1.00  ink=#9EAA9E  ☀昼
16:30  #F2EDDF  #EFE6D2  light=0.96  ink=#9CA898  ☀昼
18:00  #E5D4BC  #EFCFAA  light=0.80  ink=#A29584  ✦暮
19:30  #6E6A66  #8C7B6C  light=0.52  ink=#5E5F5C  ✦夜
20:30  #3E4650  #525A60  light=0.32  ink=#414A53  ✦夜
24:00  #353D46  #4A5258  light=0.28  ink=#39424B  ✦夜
```

**核心好处**：
- 同一函数连续插值，晨昏过渡**自然**（不会出现 17:00→18:00 闪一下"夜里"）；
- `light` 直接用作夜晚/晴雨压暗层 alpha → 整园光照统一；
- `ink` 直接喂给远山 → 山色随时间渐变（晨青山、夜墨山）。

## 六、远山三叠（修复「山没了」的关键）

```kotlin
fun drawMountains(sky, season, weather, t) {
    val baseY = H * 0.335f
    listOf(
        Triple(amp=H*0.055, y=baseY-H*0.045, alpha=0.30, drift=t*1.2f, seed=11),
        Triple(amp=H*0.075, y=baseY-H*0.012, alpha=0.45, drift=t*2.0f, seed=23),
        Triple(amp=H*0.095, y=baseY+H*0.022, alpha=0.62, drift=t*3.2f, seed=37),
    ).forEach { (amp, y, alpha, drift, seed) ->
        // 取若干控制点 (qx,qy)，用 sin(i·k+seed) 给出非周期地形
        // 用 quadraticCurveTo 平滑
        canvas.apply { save(); alpha=alpha; fillStyle=sky.ink; }
        // 横向 repeat = -1..1，让远山无缝连绵
        // 冬季 / 雪天：再描一条山顶白色"雪线"，lineWidth 自远而近 3 → 2
    }
}
```

要点：
- **三层 diff drift speed** → 视差感（远慢近快）
- **季节色偏** = `mix(ink, mist_season, 0.18)`
- **雪线**只挑 `py < y - amp*0.55` 的高处描白
- 山脚过渡靠 L4 雾带柔化

## 七、四季氛围粒子（修复「落叶萤火虫错了」）

通用原则：**粒子的位置/旋转/状态必须是 `t` 的函数**——一旦脱离时间，便只是死贴图。

### 7.1 春 · 花瓣（drawPetals）
- 16 粒，确定性种子 333
- 位置：`y = (t·sp + ph) mod H*0.92 + 0.04H`，`sp ∈ [56, 92]` px·s⁻¹
- 摇摆：`x += sin(t·0.7+swp+y·0.006) · sway`  (sway 30~60)
- **自转**：`rot = t·(0.8+rand·0.8)+rp`（粒子独立速率）
- 形状：四瓣贝塞尔，不是椭圆

### 7.2 秋 · 落叶（drawLeaves）
- 14 粒，确定性种子 444，色相在 `#C89A5E / #B9854C / #D2A968` 取
- 自转幅度更大（`rot = sin(t·1.4+swp)·1.2`，可在 ±1.2 弧度来回）
- 含主叶脉
- 速度比花瓣快 18%

### 7.3 夏夜 · 萤火虫（drawFireflies）
**核心原则：只画「光」，不画虫身。**
- 22 粒，确定性种子 888
- 位置：低空 `y ∈ [0.50H, 0.92H]`
- 游走：双层正余弦叠加 `x = bx + sin(...)·ax + sin(...)·ax·0.3`
- **呼吸式明灭**：`glow = 0.35 + 0.65·|sin(t·(0.7+fs)+p1)|³`（指数让闪烁更"扑闪"）
- 渲染：径向渐变光晕 + 中心 2.2px 实心圆 → 远看是"光斑"，近看是"微火"

### 7.4 飞鸟（drawBirds，仅 CLOUDY/CLEAR 昼）
- 周期 26s，前 32% 时间在画面从左掠向右上方
- 4 只成"人"字形，翅频 `sin(t·7+i)·0.35` 让翅膀轻微拍动
- 一组过时下次循环再生

## 八、天气系统（修复雨/雪单调）

| 天气 | 渲染 | 额外影响 |
|---|---|---|
| CLEAR | 无 | 全色 |
| CLOUDY | 3 层浮云（`drawClouds`） | 太阳 / 月亮度 → 55% |
| RAIN | 70 条斜雨 + 地面水汽 | 天空去饱和 22% → 灰青；日夜压暗不变 |
| SNOW | 60 颗绕摆雪粒 | 天空冷灰 18% + 加雪线 |
| FOG | 3 条横向雾 | 远山与天体全部隐藏（避免穿帮） |

下雨天不再画太阳 / 月亮（FOG 同样），避免「雨夜满月」这种不协调感。

## 九、夜晚渲染（压暗 = 整园统一光照）

不再硬编码 alpha。在 `drawGarden` 末尾加：

```kotlin
val dim = 1f - sky.light                // 0 ~ 0.72
if (dim > 0.02f) {
    canvas.drawColor(Color.argb((dim * 107).toInt(), 30, 38, 48))  // ≈ 0..42%
}
```

整园统一变暗；同时雨/雾各自再染一层灰。这样从午后 1.0 光强到子夜 0.28 是**渐变连续**的，跳秒才闪是断点。

## 十一、保留的小心思

- **留白比**：天空 40%+ 是干净底色，不堆元素
- **湖泊不画**：墨园是庭院，不是江山图
- **鸟只一群**：飞一次就够，循环节拍 26s
- **不要炫技过渡**：季节切换用现有 `seasonPngCache` 即可，加 1s 渐隐足够了
- **可访问性**：关闭 `reduceMotion` 时，粒子的 `t` 自变量乘 0，或保持静止

## 十三、v3.1 变更（用户反馈迭代）

| 反馈 | 解法 |
|---|---|
| 花圃与植物离得太近、没有距离感 | **透视布局**：格子尺寸随景深缩放（后排 0.84 → 前排 1.14），行/列距拉开（stepX 0.50→0.56、stepY 0.26→0.315），草坪砖按 0.92 绘制留缝；植物随所在格子透视缩放 → 远小近大 |
| 飞鸟横着飞很奇怪 | **重绘飞鸟**：水滴形身体 + 头/喙 + 尾羽 + 双翅上下拍动（`sin(t·9)` 拍翅相位），沿微弧线斜向爬升掠过，队形 4 只各自轻微起伏 |
| 花圃底部椭圆阴影说不上来好坏 | **淡墨晕染地面**（`drawGroundWash`）：4 个错位径向渐变晕斑叠出不规则"墨染"边缘，颜色取季节 `ground` 色 → 不再是生硬单椭圆 |
| 四季背景差别不大、只有秋是黄的 | **四季调色拉开**：sky/hor 染色比例提高，新增 `accent` 霞色（春粉/夏翠/秋杏/冬青）按日光强度混入地平线；远山季节染色 0.18→0.30；春季远山腰新增桃粉晕斑；新增季节 `ground` 色 |
| 缺少生动感灵动感 | **蝴蝶**（春/夏昼间 2 只，双翅 10Hz 开合、8 字游走）；**石灯笼夜晚亮灯**（暖光 + 烛光微闪） |

## 十四、v3.2 修订（庭院装饰重绘 + 抚触摆幅收敛）

| 反馈 | 解法 |
|---|---|
| 抚触摆幅 5.5 倍过大 | **`drawGarden` 摆幅系数收敛**：`(1+e*4.5) → (1+e*1.6)`；高频轻颤 `e*3.5 → e*1.1`（5.2Hz→柔），旋转 `e*2.2 → e*1.0`；峰值约 2.6 倍（仍比自然摆动明显，但不再"狂抖"） |
| 后侧篱笆横梁是锯齿折线不漂亮 | **分段绘制**（`drawFenceRun`）：col=0 左侧与 row=0 后侧各自独立成一段直线，相邻桩连线随景深自然收放；新设计：青竹色立桩 + 双道横绑 + 绳结 + 竹节；白天不透明度 0.58（夜 0.86） |
| 不知道石灯笼是哪个 / 夜晚效果看不清 | **石灯笼放大 + 锚点修正 + 绘制顺序重排**：① 体量系数 `1.0 → 1.65`；② 锚点由"row=n-1, col=0"（实际等距投影下的右前下角）改为"row=n-1, col=n-1"（真正的左前角），左外推 1.55 stepX；③ 绘制顺序从"草坪砖之后、植物之前"改为"全部植物之后"，避免被前景植物遮；④ **新增地面暖光池**（径向渐变贴地 `r=78s`）让夜间一眼认出 |
| 汀步石像水洼不像石头 | **鹅卵石重绘**（`drawSteppingStones`）：径向渐变（中亮边暗）+ 顶面高光 + 少量苔点；不再使用 `arc()+stroke` 边框；椭圆轴角 `±0.04~0.06`，不再像平贴圆盘 |
| 默认提示未说明灯笼位置 | **顶部说明新增**：「🏮 **石灯笼**在花园**左前方**（花圃左下角外侧），入夜自动亮起暖光、地面映出光池」 |

新层序：地面墨染 → **木栅栏（两道独立直线段）** → 草坪砖 → **飞石（菱形错落）** → 植物 → **木灯笼（左前外，行灯形，夜间暖纸光 + 烛芯 + 地面光池）** → **鹿威し（右前，3.6s 周期转 + 击水溅）** → 苔点 → 压暗层。

## 十五、v3.3 重设计（**整套「墨园·庭」微缩枯山水**）

整体思路修正为：**「墨园不是一片装饰，是一个有结构、有故事的小庭园」**。三段景深：远（远山+雾+背景树）/ 中（花圃+庭内布置）/ 近（飞石路径+苔点）。

### 反馈清单

| 用户反馈 | v3.3 解法 |
|---|---|
| 中间红框元素突兀 | `drawMountains` 末尾那两段 `rgba(255,255,255,0)` + 中间色椭圆的"硬切三明治"雾带 → **整体移除**，改为 3 段大范围径向渐变柔和混入天空（α 峰值仅 0.18），天空与远山自然过渡，无任何水平条带 |
| 3×3 时植物太大、占满 | `PLANT_FACTOR = 0.55` **统一缩放**；3×3 / 4×4 / 5×5 都按格子基准的 55% 绘制；植物原本是 1.02×格子，这下 3×3 单株也只占每格 50%，整体不再喧宾夺主 |
| 石灯笼突兀、建议木质 | **改为木灯笼（行灯 / 置き灯 型）**：① 木色暖棕 + 暗木 `#5C3E2A`；② 体量系数 1.65→**1.10**（直接砍 33%）；③ 形态变方盒灯室 + 十字窗棂 + 八角翘檐 + 宝珠脊尖；④ 夜间效果改"白纸透暖光 + 微烛芯 + 加色光池"，更像古园"夜明"之意；⑤ 锚点精确到左前角 `row=n-1, col=n-1` 左外推 1.85 stepX，缩更左 |
| 汀步石看不清、只见一块 | **飞石重写**：① 锚点移到 `row=n-1, col=n-1` 右外推 0.85b 处；② 三块尺寸差异、方位错落——近、远两枚各 20-22s 长轴、中间一枚 18s，形成有效"路径感"；③ 每块加 ±0.10~0.22 弧度倾斜（不再是平贴圆盘）；④ **顶面高光带随石头旋转**（之前不随转；现在 save/rotate/restore），立体感强 |
| 篱笆不像篱 | **竹篱整段移除**，改为**简朴木栅栏**：一道横木 + 细立柱 + 顶小帽；两段（col=0 / row=0）依旧独立成直线；细木桩不刻意追求"墨绿"色相，回归木质 `#785C2E`/`#56442E`——更朴素、更像真正围栏 |
| 整体概念：花园还该有什么 | **新庭园元素系统**：① **木灯笼** ② **鹿威し（鹿脅し / 竹水鼓）**：3.6s 周期转动、击水瞬间飞溅+水波——日本庭园经典"声+动"；③ **蹲踞（石水钵 / 手水钵）**：不规则石盆 + 中央立石 + 旁置小竹勺；④ **背景主树**：随季节切换的 樱(春)/柳(夏)/枫(秋)/松(冬)；⑤ **苔点**：4 团小绒点散落在园外，柔化人造围栏与花圃的接缝 |

### 新层序（v3.3 花园部分）

```
天空 → 天体 → 三叠远山 → 柔和雾带（无硬切） → 浮云 → ┐
地面墨染 → 背景主树 → 木栅栏 → 草坪砖 → 飞石 → 蹲踞 → 植物 → 木灯笼 → 鹿威し → 苔点 → 压暗 → vignette
```

夜灯笼：木质基础 + 暖黄纸窗 + 烛芯微闪 + 地面椭圆光池  
鹿威し：杠杆式竹管、约每 3.6s 抬起后重重落下"咚"击水（带飞溅+水波）  
蹲踞：画面外右下角（与灯笼位置错开），竹勺斜置旁

## 十七、v3.3-fix3 修订（2026-07-24 第六轮）

**起因**：用户反馈两件事：
1. 红框里的篱笆穿到花圃里（图片中篱笆线穿过右侧多个花圃）
2. 花圃间距太大，整个花园显得松散

**根因**：
1. 旧 `drawFence` 用「水平/垂直线」连 cell 端点——但等距投影下后沿本来就是斜的，水平线必然切过后排每个 cell
2. v3.1 → v3.3-fix 把 `stepX/Y` 拉开到 `tile*0.56 / 0.315`（为"距离感"），结果对 4×4 / 5×5 而言花圃过宽

**修复**：

| 项 | 旧 | 新 |
|---|---|---|
| 篱笆走向 | 后沿：水平线；左沿：垂直线 | 后沿：沿钻石 NE 边（左上→右上）；左沿：沿钻石 NW 边（左上→左下） |
| 篱笆位置 | 穿过后排 cell | 外推到 cell 后侧/左侧锚点，沿钻石外沿走 |
| stepX | `tile*0.56` | `tile*0.44`（收紧 21%） |
| stepY | `tile*0.315` | `tile*0.245`（收紧 22%） |

**保留的几何定义**（钻石三顶点）：
- 北顶点：`cells[0]`（r=0, c=0）→ 最上
- 东顶点：`cells[n-1]`（r=0, c=n-1）→ 右后
- 西顶点：`cells[(n-1)*n+0]`（r=n-1, c=0）→ 左后

篱笆沿（北→东）和（北→西）两条边画，每条边上等距插立柱。三种 grid 尺寸都验证过——篱笆不再穿花圃。

## 十八、v3.3-fix5 修订（2026-07-24 第八轮）

**起因**：v3.3-fix2 因为"远山成硬灰带"把整段 `drawMountains` 删了，只留一条地平线渐变。用户看到这一轮反而觉得太"空"，明确要求把远山**加回来**，但有三个具体诉求：

1. **三层改两层**——画面不该被远山抢戏
2. **柔和秀丽**——不要硬切横带
3. **山上有点缀元素**——松树、小亭之类

### 几何决定

把远山从"占画面 22%"的厚重层，压缩成"地平线一条薄带"（占画面 ~10%）：

| 参数 | v3.3（旧） | v3.3-fix2 | v3.3-fix5（当前） |
|---|---|---|---|
| 层数 | 3 | 0 | **2** |
| 远层峰顶 | H×0.245 | — | H×0.308 |
| 近层峰顶 | H×0.313 | — | H×0.348 |
| 山脚 | H×0.420 | — | H×0.402 |
| 振幅 | 0.055/0.075/0.095 | — | 0.034/0.026 |
| 远层 α | 0.30 | — | 0.30 |
| 近层 α | 0.62 | — | 0.46 |
| 顶部硬切 | 无（但叠厚成硬带） | n/a | **有竖向渐变柔化** |

### 柔和秀丽的关键改动

旧版每个远层 fill 一个色块 → 3 个色块叠在一起就是"硬灰带"。
新版每个远层 fill 一条**竖向渐变**：
- 渐变起点：`peakY - amp`（山峰最高点）
- 渐变终点：`peakY + amp × 2.4`（山体中部）
- stop 0：`rgba(r,g,b,0)` —— 山顶透明融入天空
- stop 0.45：`rgba(r,g,b,α)` —— 已达到目标不透明
- stop 1：`rgba(r,g,b,α)` —— 维持到山脚

效果：山脊轮廓只剩 0.45×振幅的"半透明过渡区"，肉眼看到的是**柔化的黛色剪影**，而不是硬边。

### 山麓点缀

- **远层**（淡黛蓝）：山脊不点元素，保持极远
- **近层**（实色黛蓝）：沿山脊 5 棵**小松树剪影**（3 层针叶三角 + 短干，按季节染色）+ 1 座**小亭**（翘檐 + 双柱，雪天屋脊点白）
- 位置用同一噪声公式 `Math.sin(i*1.3+L.seed)*0.6 + Math.sin(i*2.7+L.seed*1.7)*0.4` 反查 y，保证树/亭脚踩在山脊上

季节染色：
- 春：`#4A684E`（嫩绿）
- 夏：`#3A5C44`（浓绿）
- 秋：`#6E5C36`（暖褐）
- 冬：`#56686C`（冷青）

雪天额外给树尖、亭顶加白色小三角。

### 关键 bug 修复（开发过程）

第一版把 `mixRgbHex(rgb, hex, t)` 当成"两 rgb 混合"用，传入 `sky.ink`（rgb 字符串）当作 hex 参数，结果 `hex2rgb('rgb(...)')` 返回 `[NaN,NaN,NaN]`，整条远山抛出 `addColorStop: rgba(NaN,...)` 异常、画面只渲染天空。

1. 层数 3→2
2. 每层 fill 改为 `LinearGradient`（山顶→山腰的竖向渐变）
3. 山脊点缀：新建 `drawMountainTrees(scene, season, snow)` + `drawPavilion(x, y, snow)`，复用 `drawPineTree` 资产

## 第十九章 v3.4 围合与园路

### 用户反馈（2026-07-24）
> 整个花园只有花圃和植物吗 你再思考下 总感觉设计的下面这个不像是个园子，没有园子这个整体概念。你思考下 花园还应该包含什么元素

### 诊断
当时 L6 只有"菱形草坪 × 植株"，花圃与植物是**软景表皮**；缺的是**硬景骨架**——围合、园路、水、亭榭、主景树这些定义"园"的元素。一片花田≠一间园。

### 本轮实现范围
用户从三组硬景骨架里先选「围合 + 园路」（其它两组——水池+桥+亭、主景树+石灯籠——留待后续）。

### 新增/改造的函数
| 函数 | 作用 | 层级顺序 |
|---|---|---|
| `drawEnclosure(cells, n, sky, season, t)` | 后墙 + 墙顶绿篱（粉墙/瓦顶/漏窗/随季绿篱） | L6 第 1 步（地面晕染之后、草坪砖之前） |
| `drawGardenPath(cells, n, sky, t)` | 蜿蜒石径（路缘/路面/中线虚痕/隔点踏石） | L6 第 3 步（草坪砖之后、植物之前） |
| `drawMoonGate(cells, n, sky, t)` | 月洞门（入园口符号） | L6 第 5 步（所有植物/木灯笼之后），盖在前景之上 |
| `drawFence` / `drawSteppingStones` | 删除调用 | — |

### 关键设计决定

1. **围合采用"后墙 + 墙顶绿篱"水平背板**，而不是沿钻石 NE/NW 边的绿篱：
   - 初版沿钻石后沿两条边画绿篱+北顶点粉墙，被后排草坪砖完全盖住（在 L6 第 1 步就画，砖覆盖后排水圃）。根因：等距投影下后排 cell 的草坪砖会延伸到钻石边外侧。
   - 改为：在山脚与花园之间（y≈666–730）的空白带里画一道粉墙（弧顶 + 平底紧贴花园背），墙顶再种绿篱（厚笔触 + 叶丛，4 季变色）。墙底 bottomY=topY+bandH(topY=c0.y-c0.size*0.95, bandH=64) 紧贴花园背，无空缝。
   - 墙顶绿篱色板：春 `#6E9A5C` / 夏 `#4F8866` / 秋 `#9C7B3E` / 冬 `#8EA1AB`。
2. **园路采用"中心线 S 波"**：
   - `d=1..Dmax` 深度参数，`frac=(d-1)/(Dmax-1)`。
   - `x = cx + sin(2π·frac) · stepX·0.92 · sin(π·frac)`：前/后端 amp 归零（正对 cx=S 中线），中段左右各一峰（±stepX·0.92），形成对称 S 编织。
   - 初版用 `sin(π·1.5·frac)` 导致入园点 x=cx-83（偏左），月洞门虽立 cx 但路从左侧进——视觉错位。修后入园端正对 cx。
3. **月洞门必须在最顶层画**（所有植物/木灯笼之后），否则被前景中央的植株盖住。
4. **园路可被植物遮挡是合理的**——真实园路穿过花圃之间，植物压一点路缘反而显"自然"；路面与路缘加深（`rgba(238,228,204,0.98)` / `rgba(172,158,128,0.7)`）保证主体可读。

### 第二十三章 v3.4e 远山底部水平硬带修复

**问题**：用户反馈画面里"两条清晰横线"。Playwright 全画面扫描定位到两条贯穿全宽的水平硬色带：
- y=522/523 spread=3–4 rowDiff=34–37 → baseY 顶边
- y=549    spread=3   rowDiff=41   → baseY+27 底边
行内色差 spread<5 + 行间 rowDiff 极大 → 几何上的水平硬色带，不是自然渐变。

**根因（两层）**：
1. **第一层**：`drawMountains` 末尾的「地平线柔光带」`fillRect(0, baseY-2, W, H*0.022)` 是一段贯穿全宽的水平 fillRect（30px 高、竖向渐变）。其顶/底两端形成两条清晰水平硬边。注释说"极淡"实际非常显眼——**fillRect 本身就是水平色带，不管 alpha 多低都形成硬边**。
2. **第二层（更隐蔽）**：每层远山 fill 路径 `moveTo(... baseY)` + `lineTo(... baseY)` 把封底画到 baseY 一条水平线上，且渐变 stop 1 的 alpha=满 → baseY 处的水平封底线就是**远山实色线**。

**修复**：
1. 删除第一层 `fillRect` 整段（5 行 + save/restore）。
2. 渐变底部 stop 的 alpha 由 `${L.alpha}` 改为 `0`（远山脚自然淡入）。
3. 渐变终点由 `L.peak+L.amp*2.4` 改为 `baseY+H*0.05`（约 y=587）。
4. 填充路径两个底点 `baseY` → `groundBlend`（= baseY+H*0.05），水平封底线被 `drawGroundWash` 的钻石径向晕染覆盖。

**几何与 alpha 推算**：
- baseY=H*0.402=522.6，groundBlend=H*0.452=587.6
- layer 0（peak 322, amp 94）渐变范围 228–588，baseY 处 t=0.694、alpha ≈ 0.30×0.329 ≈ **0.10**（远山颜色非常淡，自然淡入地面）
- layer 1（peak 385, amp 75）渐变范围 310–588，baseY 处 t=0.620、alpha ≈ 0.46×0.427 ≈ **0.20**

**验证**（v3.4d 同套扫描脚本 `hard-edge scan`）：
- 修复前：y=522/523/549 三处贯穿全宽水平硬带
- 修复后：**`CLEAN — no horizontal hard edges remain.`**
- Playwright 5 状态截图 0 报错；雨/雾/多云天气校验亦 0 报错。

**教训（Canvas 通用）**：
- `fillRect(0, x, W, h)` 即使 alpha 极低，也会因为「行内色差=0、行间色差=渐变」而被肉眼读为「清晰的水平色带」。想画水平柔光带必须用径向/非线性 alpha 分布，或干脆删除让其他渐变接管。
- 任何几何上的"水平封底线"（如远山 fill 的 `moveTo(... baseY)`）都会在画布上形成接缝，除非该处的填充 alpha 已经极低或被下层覆盖。

### 第二十四章 v3.4f 月相重写 + 远山脚自然融合

#### A. 月相重写（用户消息5）

**问题**：用户截图显示除满月外，蛾眉/盈凸/亏凸三个月相形状怪异，"不像是圆月的一部分"。

**根因（旧 evenodd 算法）**：挖洞椭圆高度固定 = 外圆半径 r。椭圆在垂直方向完全落在外圆内，`evenodd` 仅在水平方向区分奇偶 → 亮面被切成"中间暗椭圆 + 左右各一个月牙"的怪异形状（盈凸显示成中间一道暗带+两侧月牙）；盈/亏凸把不该出现的暗椭圆/亮椭圆都画到了中央。

**修复（标准月相算法）**：亮面 = 外圆半周 + 半椭圆弧闭合，半椭圆 x 半径 `rx = r · |cos(2π · phase)|`，椭圆方向随 phase 决定凸向：

| phase 区间 | 月相 | 外圆 | 椭圆方向 | 实测亮区（中心行） |
|---|---|---|---|---|
| <0.25 | 蛾眉月 | 右半（顺时针顶→底） | 右凸（anticlockwise=true）| 右侧细月牙 |
| 0.25–0.5 | 盈凸 | 右半（顺时针顶→底）| 左凸（anticlockwise=false）| 右侧大半 `[120..173]` |
| 0.5 | 满月 | 整圆 | — | 全圆 `[114..173]` |
| 0.5–0.75 | 亏凸 | 左半（逆时针顶→底）| **右凸（anticlockwise=true）** | 左侧大半 `[114..167]` |
| >0.75 | 残月 | 左半（逆时针顶→底）| 左凸（anticlockwise=false）| 左侧细月牙 |

> 关键！首版把亏凸分支的椭圆方向写成了 `phase > 0.75`（`anticlockwise` 与凸月分支完全相同），结果 phase=0.60 渲染成"左侧细月牙"（实为残月形状）——亏凸是 >50% 亮的大半月，必须右凸（与盈凸相反方向）。**修正为 `phase < 0.75` 后，phase=0.60 亮区 `[114..167]`（接近右侧满圆宽度），是 phase=0.40 亮区 `[120..173]` 的水平镜像**。

**验证**（Playwright 自动化 `verify-moon-v34f.js`，逐像素按 lum>150 提取月亮 bbox 内的亮 x 范围）：

- phase=0.40 盈凸：y=169 亮 `[120..173]` len=54，右侧 ~90% 亮、暗月牙在左 ✓
- phase=0.50 满月：y=169 亮 `[114..173]` len=60 = 全圆 ✓
- phase=0.60 亏凸（修正后）：y=169 亮 `[114..167]` len=54，左侧 ~90% 亮、暗月牙在右 ✓
- 0 errors；截图存档 `test-shots/v34f-moon-{crescent,waxing,full,waning}.png`

#### B. 远山脚自然融合（用户消息4 的远山部分）

**问题**：用户"不想要这么直的地平线"，希望远山与下方花圃/植物/天空整体融合更自然。

**像素诊断**：远山脚（y≈380–604）原本已平滑；真正硬边在花圃（y≈764–852 密集植物）。先把远山山脚的几何直线消除，再处理花圃。

**修复**：
1. 山脚低频起伏：新增 `footY(u) = groundBlend + (sin(u·2.3 + seed·0.5)·0.7 + sin(u·4.7 + seed·1.3)·0.30) · H·0.035`，让原本水平的封底线变成与山脊呼应的低频起伏（不再是一条直线）。
2. 远山脚下薄雾：hzTop = baseY − H·0.015、hzBot = baseY + H·0.14，竖向渐变 top/bottom alpha 均 → 0（沿用第二十三章 v3.4e 教训——绝不再用贯穿全宽 fillRect 画水平硬带），中点 alpha = 0.18 + 0.05 · sky.light，雾色取地面暖白 #F3F0E7，让远山"沉"入地平雾。

```js
const groundBlend = baseY + H * 0.05;
const grad = CTX.createLinearGradient(0, L.peak - L.amp, 0, groundBlend + H * 0.04);
grad.addColorStop(0,    `rgba(${cr},${cg},${cb},0)`);
grad.addColorStop(0.45, `rgba(${cr},${cg},${cb},${L.alpha})`);
grad.addColorStop(1,    `rgba(${cr},${cg},${cb},0)`);   // 底部 alpha→0，淡入地面

const footAmp = H * 0.035;
const footY = (u) => groundBlend + (Math.sin(u*2.3 + L.seed*0.5)*0.7 + Math.sin(u*4.7 + L.seed*1.3)*0.30) * footAmp;
// fill：山脊左→右(quadratic)，山脚右→左用 footY(i/(pts.length-1)) 让封底起伏

// 末尾薄雾
const hzTop = baseY - H * 0.015, hzBot = baseY + H * 0.14;
const hz = CTX.createLinearGradient(0, hzTop, 0, hzBot);
hz.addColorStop(0,    'rgba(243,240,231,0)');
hz.addColorStop(0.45, `rgba(243,240,231,${0.18 + 0.05*sky.light})`);
hz.addColorStop(1,    'rgba(243,240,231,0)');
CTX.fillStyle = hz; CTX.fillRect(0, hzTop, W, hzBot - hzTop);
```

## 第二十七章 v3.4i 蝴蝶停留 + 雾重做

### 1. 蝴蝶增加停留状态（飞 → 停 ≈1s → 飞）

为每只蝴蝶加一个闭包数组 `bfState[]` 保存状态：

```js
const bfState = [];   // 每只蝴蝶一个 { mode, until, px, py, amt, dir }

if (st.mode === 'fly') {
  if (t > st.until) {                      // 飞够 4–9s 就停
    st.mode = 'rest';
    st.until = t + 1.8 + Math.random()*0.6;// 总停留 ~1.8–2.4s（视觉静止 ~1s）

} else {
  if (t > st.until) { st.mode = 'fly'; st.until = t + 4 + Math.random()*5; }
}
```

**平滑过渡** `amt`（0=飞，1=停）：

```js
const target = st.mode === 'rest' ? 1 : 0;
st.amt += (target - st.amt) * 0.07;        // 指数平滑 ≈ 0.55s 走完大半程

const x = fx + (st.px - fx) * st.amt;
const y = fy + (st.py - fy) * st.amt;
```

### 2. 雾的形状重做（从硬横条 → 柔和雾团）

**问题**：旧 `drawFog` 用 3 条贯穿全宽的椭圆带（`ry=62`、`W*0.9` 宽、上下漂移），看起来像横挂的色块，**违反 v3.4e 教训**（`fillRect` 即便低 alpha 也是水平硬带；几何水平封底线同理）。

```js
function drawFog(t){
  // 1) 地面柔雾：竖向渐变 fillRect，顶/底 alpha→0（与 v3.4e 教训一致）
  const base = CTX.createLinearGradient(0, H*0.22, 0, H);
  base.addColorStop(0,    'rgba(225,225,216,0)');
  base.addColorStop(0.55, 'rgba(228,228,219,0.10)');
  base.addColorStop(1,    'rgba(228,228,219,0.26)');
  CTX.fillStyle = base; CTX.fillRect(0, H*0.22, W, H*0.78);

  // 2) 多团软雾：径向渐变边缘天然透明，缓慢横向漂移 + 上下轻浮
  for (let i = 0; i < 6; i++) {
    const y = H*(0.34 + 0.11*i) + Math.sin(t*0.18 + i*1.7)*H*0.025;
    const drift = (t*(5 + i*1.6)) % (W + 480) - 240;
    const x = i*W*0.21 + drift + W*0.1;
    const rw = W*(0.30 + (i%3)*0.06);
    const rh = rw*(0.34 + (i%2)*0.05);              // 扁椭圆、柔和
    const a  = 0.15 - i*0.015;
    CTX.save(); CTX.translate(x, y); CTX.scale(1, rh/rw);
    const g = CTX.createRadialGradient(0, 0, 0, 0, 0, rw);
    g.addColorStop(0,    `rgba(233,233,225,${a})`);
    g.addColorStop(0.55, `rgba(230,230,221,${a*0.5})`);
    g.addColorStop(1,    'rgba(230,230,221,0)');
    CTX.fillStyle = g; CTX.beginPath(); CTX.arc(0, 0, rw, 0, 7); CTX.fill();
    CTX.restore();
  }
}
```

## 第二十九章 v3.4k 远山高低错落（山脚 + 地平线衔接继续不变）

**问题反馈**：「v3.4j 山脊是更清晰更绵密了，但**没高低错落感**」——用户希望看到多个明显的高低峰谷参差有致，而不是一条相对均匀起伏的曲线。

### 根因：v3.4j 的 noise 用了 `Math.abs()`，把波谷翻成波峰

```js
// v3.4j（错）
const noise=Math.sin(u*5.0+L.seed)*0.60
           +Math.sin(u*10.0+L.seed*1.7)*0.32
           +Math.sin(u*17.0+L.seed*2.9)*0.15;
const n=Math.min(1, Math.abs(noise));     // ❌ abs 把负半周翻正 → "全是凸起、无深谷"
pts.push([px, L.peak - L.amp*(0.32+0.82*n)]);
```

`abs` 让 n ∈ [0,1]，但因为三个 sin 同时过零概率低、且振幅叠加后 n 很少落到 0.3 以下，结果整条山脊**一系列近似等高的尖包**——看着绵密，但**没有真正的低谷**，自然没有错落感。

### 修复：带符号多频叠加 + 长波不再垄断

```js
// v3.4k（对）
const segs=20, pts=[];                                          // 段数 10 → 20 更绵密
const TAU=Math.PI*2;
const noise=Math.sin(u*TAU*1 + L.seed      )*0.22      // 长波：仅轻微整体大势（不垄断）
           +Math.sin(u*TAU*3 + L.seed*1.3  )*0.38      // 3 峰：主峰骨架
           +Math.sin(u*TAU*5 + L.seed*2.1  )*0.25      // 5 峰：副峰（与 3 拍频 → 非对称起伏）
           +Math.sin(u*TAU*8 + L.seed*2.7  )*0.15;     // 8 细节：细微褶皱
const n=Math.max(0, Math.min(1, (noise+1)*0.5));                // 归一化 0..1
pts.push([px, L.peak - L.amp*(0.08+0.95*n)]);                  // 谷更深、峰更高
```

关键变化：
1. **去掉 `abs`**，noise 保留符号 → 真正的高低起伏
2. **长波 0.45 → 0.22**：v3.4k 第一版曾用 0.45，结果整条山脊被拉成"右高左低"单边趋势，错落感被压住；降到 0.22 后长波只做轻微倾斜
3. **新增 5 峰分量**：与 3 峰叠加产生拍频，自动形成非对称的"高-低-更高-最低-最高-..."多峰分布
4. **基线 0.32 → 0.08**：谷能落得更深，峰谷对比 amp×0.95（≈前 1.1 倍）
