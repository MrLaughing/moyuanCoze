## 1. 架构性根本差异（解释绝大多数差异的根因）

| 维度 | Web 原型 | Android 实现 |
|------|----------|--------------|
| 渲染驱动 | `requestAnimationFrame` 每帧（~60fps）全量重绘，`t=now/1000` 连续时间 | `GardenRendererView.onDraw` 中：背景 `sceneBitmap` **仅在 `sceneDirty` 时重绘一次**并缓存 |
| 动画范围 | 全部元素随时间 `t` 动（山漂移、云飘、雾团漂、月呼吸、星闪烁、蝶/鸟/花瓣/落叶/萤火虫） | 仅 **蝴蝶**（`drawButterflies`，逐帧 `SystemClock`）与 **植物**（`drawPlants`，`ambientPhase` 摇摆）逐帧动；其余全部烤进静态缓存 |
| 坐标基准 | 固定 `W=800, H=1300`，绝对像素 | 任意 `w×h`，按比例 `sf = w/800` 缩放（蝴蝶额外 ×1.4 放大适配手机） |
| 调色来源 | `skyAt(hour)` 按**小时**插值关键帧 + 季节 `tint` + 天气染色 | `SEASON_COLORS[season].sky` 仅按**季节**固定色，`dayLight(hour)` 只用于远山 alpha |

**推论**：因为场景是静态缓存，Android 端所有"依赖 `t` 的动效"在原型里是活的、在 Android 里是冻结的（远山不漂移、云不飘、雾团不漂、月不呼吸、无星星、花瓣/落叶/萤火虫定格）。这是性能权衡（原型是调试沙盘、Android 是生产），但确实偏离了原型的"活景"观感。

## 2. 子系统逐项比对

### 2.1 天空 Sky
| | Web `drawSky`/`skyAt` | Android `drawPremiumBackdrop` | 差异 |
|--|--|--|--|
| 颜色来源 | 按小时在 `SKY_KEYS` 关键帧插值（晨/昼/暮/夜显著不同），再混季节 `tint.sky`、季节霞 `accent`、天气染色（雨/雪/雾） | 2 段竖向渐变 `WHITE → colors.sky` + 一个径向"地平线高光"，`colors.sky` 为**固定季节亮色** | **明显差异** |
| 昼夜 | 夜间天空混入 `sky.ink` 明显变暗 | **夜间不压暗**，天空永远是亮色 | **功能性缺失**：22:00 仍是亮天 |
| 天气染色 | RAIN/SNOW/FOG 各染色 | 无（天气只影响 `drawWeatherEffect` 的雨/雪/雾层） | 差异 |
| 细纹理 | 26 条极淡（α0.05）水平线 | 无 | 细微差异 |

> ⚠️ **最值得修的差异**：原型夜间天空是暗的（配月亮+星星），Android 夜间天空仍是亮色 —— 夜里会看到"亮天 + 月亮"的违和组合。若需对齐原型，应让 `drawPremiumBackdrop` 按 `dayLight(hour)`（或 `skyAt`）插值夜色。

### 2.2 太阳 Sun
| | Web | Android `drawSun` | 差异 |
|--|--|--|--|
| 位置 | `cx=W*(0.80+0.06sin(pπ))`, `cy=H*(0.085-0.02sin(pπ))`, `p=(h-6)/11` | 完全一致（×`sf`） | **一致** |
| 光晕/中光/主体/高光/暖带 | 颜色与 α 完全一致 | 完全一致（×`sf`） | **一致** |
| 变暗 | CLOUDY 时 `dim=0.55` | CLOUDY **或 OVERCAST** `dim=0.55` | 近似（Android 多覆盖 OVERCAST，更合理） |
| 显示时段 | 6:00–16:59（`h>=6 && h<17`） | 6:00–17:00（`h in 6..17`，含 17） | 边界差：17:00 Android 同时画**太阳+落日** |

### 2.3 落日 Sunset
| | Web | Android `drawSunset` | 差异 |
|--|--|--|--|
| 位置/半径 | `cx=0.16W`, `cy=0.145H+p*0.05H`, `r=0.032W` | 完全一致 | **一致** |
| 红晕 | 两点径向 `r*0.3→r*3.5`（`0.5→0.18→0`） | 单点径向 `r→r*3.5`（编译修复后） | 近似（晕起点不同，视觉接近） |
| 主体/高光 | `rgba(214,104,74,0.85)` / `rgba(240,160,110,0.55)` | `argb(217,214,104,74)`=`rgba(214,104,74,0.85)` / `argb(140,240,160,110)` | **一致** |
| 显示时段 | 17:00–19:29（`h>=17 && h<19.5`） | 17:00–18:00（`h in 17..18`） | **差异**：Android 落日窗口短 0.5h，且 18–19 点二者都不画（见 2.5 时段空档） |

### 2.4 月亮 Moon
| | Web `drawCelestial`(night) | Android `drawMoon` | 差异 |
|--|--|--|--|
| 位置 | `mx=0.18W`（左上，避让右上统计文字）, `my=0.13H` | `mx=0.82W`（右上）, `my=0.085H` | **位置不同**：原型左上、Android 右上（App 布局差异，可解释） |
| 半径 | `r=30`（=0.0375W） | `r=0.038W` | **一致** |
| 月相算法 | 标准外圆半周+半椭圆弧，`rx=r*|cos(2π·phase)|` | 同算法（`Path.arcTo`） | **一致**（sweep 方向用 `-180/180` 等价实现） |
| 呼吸 | `breath=0.85+0.15sin(t*0.4)`（动画） | `breath=0.92`（恒定，因静态缓存） | **差异**：Android 月无呼吸 |
| 星星 | 26 颗 `sin` 闪烁星点 | **无星星** | **缺失**：夜空无星 |
| 显示时段 | 19:30–05:29（`h>=19.5 \|\| h<5.5`） | 19:00–04:59（`h>=19 \|\| h<5`） | 边界略移（约 0.5h） |

### 2.5 昼夜时段衔接（综合性问题）
原型按时段互斥切换天体：日(6–17)→暮落(17–19.5)→夜(19.5–5.5)→晨(5.5–7.5)→昼。
Android 的边界：
- 17:00 同时画**太阳+落日**（重叠）；
- 18:00–18:59 只画落日（对齐原型）；
- **19:00–19:29**：原型仍画落日，Android 已切到月亮 → 这一段 Android 二者都不画/直接月亮；
- 05:00–05:29：原型仍夜（月亮），Android 已不画月亮。

> 建议：统一以 `h<5.5`/``h>=19.5` 为夜边界，并让 17–19.5 仅落日、避免 17:00 太阳落日同帧。

### 2.6 远山 Mountains
| | Web `drawMountains` | Android `drawMountainLayer` | 差异 |
|--|--|--|--|
| 层数/配色 | 远 `peak0.248H,amp0.072H`，近 `peak0.296H,amp0.058H`；`daiBlue` 由 `tint.mist` 混蓝灰 | 远 `peak0.22H,amp0.07H`，近 `peak0.27H,amp0.06H`；用 `SeasonColors.mountainFar/mountain` | 近似（峰值/振幅略有出入，Android 远山略高） |
| 噪声公式 | `sin(TAU*1+seed)*0.22 + 3频*0.38 + 5频*0.25 + 8频*0.15` | **完全相同**（c4378fe 仅加括号） | **一致** |
| 归一化/起伏 | `n=clamp((noise+1)*0.5,0,1)`，`y=peak-amp*(0.08+0.95n)` | 同 | **一致** |
| 填充渐变 | `peak-amp→groundBlend+0.04H`，`0→α→0`（中点在 0.45） | 同（中点在 0.5） | 细微差异 |
| 山脊描边 | 宽 1.3px，`mixRgb(col,sky.ink,0.30)` α0.55 | 宽 `h*0.001`(≥1.1)，`darken(col,0.30)` α0.55 | 近似（夜色描边色 Web 混 `sky.ink`、Android 混固定 `INK`） |
| 山脚薄雾 | `baseY±…`，`0→0.18+0.05*light→0`，`rgba(243,240,231)` | 完全一致 | **一致** |
| **水平漂移** | `drift=t*0.5/0.9`，三重复制 `rep∈[-1,0,1]` 实现无缝滚动 | **无漂移**（静态） | **差异（动效冻结）** |

> 远山"高低错落"的观感两者一致（同一噪声）；唯一实质差异是原型远山会缓慢横向漂移，Android 冻结。

### 2.7 雾 Fog
| | Web `drawFog`(FOGGY) | Android | 差异 |
|--|--|--|--|
| 常驻地面薄雾 | 无（仅 FOGGY 时） | **新增** `drawAmbientFog`（永远画，`0.55H→H`，α0.12→0.18） | Android 增强（v3.4i 教训，柔化花园底部） |

### 2.8 云 Clouds
| | Web `drawClouds` | Android `drawCloudEffect` | 差异 |
|--|--|--|--|

### 2.9 蝴蝶 Butterflies
| | Web `drawButterflies` | Android `drawButterflies` | 差异 |
|--|--|--|--|
| 状态机/姿态 | 飞行↔停留，`amt` 指数平滑 0.07，侧视身体+头+触角，近/远翅 `wingR/wingN` | **完全相同** | **一致** |

|--|--|--|--|

| 动画 | 沿弧线爬升、拍翅相位 `sin(t*9)`，22s 周期 | **静态**（无 `t`，位置固定） | **差异（无动画）** |

### 2.11 花瓣 / 落叶 / 萤火虫
| | Web | Android | 差异 |
|--|--|--|--|
| 花瓣 `drawPetals`/`drawFallingPetals` | 春，随 `t` 飘落旋转 | 春(非雨雪)，**静态**（无 `t`，烤进缓存） | 动效冻结 |
| 落叶 `drawLeaves`/`drawFallingLeaves` | 秋，随 `t` 飘落 | 秋(非雨雪)，**静态** | 动效冻结 |

### 2.12 植物 / 花圃 / 地面（原型简、Android 富）
这部分 Android **远超**原型，不是"差距"而是生产增强：
- 原型：`layoutCells` 透视网格 + PNG 贴图（`seasonTile`/`plantImg`）+ `drawGroundWash` 淡墨晕染。
- Android：`GardenLayout` 网格 + `seasonPNGCache` 草坪贴图 + `drawGardenPlots`（园圃格子）+ `drawFence`（竹篱笆）+ `drawStone`/`drawMoss` + `drawPlants`（含 `PlantArchetype`、逐帧 `ambientPhase` 摇摆、枯萎态 `witherAlpha`、蜘蛛网 `drawSpiderWeb`）。

> 注：此前用户提到的"**花圃融合**（空地→花圃过渡雾带，方案②）"仍**未实现**——原型的 `drawGroundWash` 柔和过渡在 Android 端尚未等价落地。

## 4. 建议（按优先级）

1. **【高】夜间天空压暗**：让 `drawPremiumBackdrop` 按 `dayLight(hour)` 或 `skyAt` 关键帧插值夜色（否则夜里"亮天+月亮"违和）。可参考原型的 `SKY_KEYS` 表移植。
2. **【高】夜空补星星**：`drawMoon`（或 `drawScene` 夜分支）补 26 颗闪烁星点（静态即可，至少位置要对）。
3. **【中】统一昼夜时段边界**：以 `h<5.5`/`h>=19.5` 为夜，17–19.5 仅落日，避免 17:00 太阳落日同帧、19:00–19:30 空档。
4. **【中】云风格**：决定保留 Android 的"灰云带"还是换回原型蓬松白云（若要对齐原型，需重写为多椭圆簇+漂移）。
5. **【低/可选】远山漂移**：如需"活景"，可在 `sceneDirty` 之外以低帧率重绘远山（成本较高，默认建议保持静态）。
6. **【待做】花圃融合**：补 `drawGroundWash` 等价过渡（空地→花圃柔和雾带）。
